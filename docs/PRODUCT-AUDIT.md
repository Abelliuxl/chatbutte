# Chatbutte：功能审计与重构边界

审计日期：2026-10-25。依据：`Abelliuxl/chatbutte` 主线 `13f32bf` 的 README 与源码，以及 server94 `/home/ubuntu/chatbutte` 的实际部署文件。两者不一致，产品基线以线上增量为补充，而非仅照 README。

## 原有产品定位

本地优先、自带模型接口、无账号的个人 AI 对话与文生图工作台。原版原生 HTML/CSS/JavaScript，Python 同源代理；会话、配置和凭据主要保存在浏览器 localStorage，Gist 是手动备份。

## 功能盘点与新版决策

| 原版能力 | 重写后的处理 |
|---|---|
| 多个模型配置；对话/图片类型；每话题模型选择 | 保留，独立类型化配置与显式协议，不依赖模型名前缀猜协议 |
| 子话题新增、改名、删除、桌面拖拽排序 | 统一称会话；新增即进入输入；搜索、置顶、上下移提供触屏/键盘替代 |
| 独立系统提示词、历史条数、温度 | 保留；0 不再被默认值覆盖；历史 0 表示不携带过去消息 |
| 流式、Markdown、代码高亮、复制 | 重做；禁用原始 HTML，正文/思考分离，单独复制代码 |
| `reasoning_content` 与 `<think>` 展示；线上思考开关 | 保留；开关只发送选定的一种供应商字段，默认不发送 |
| 保留可见消息但截断上下文 | 保留为显式分隔符，与清空/删除严格区分 |
| 图片、文本和任意二进制文件 | 图片/文本无损保存；拒绝不支持的二进制，不假装读取 PDF |
| OpenAI Images 与 DashScope 图片 | 保留同步文生图；明确不支持异步任务/图生图 |
| 本地保存、备份回退、导入导出 | 重建版本化 IndexedDB；先校验再原子替换，保留恢复点 |
| Gist 上传/下载、变化检测 | 保留手动模式；凭据默认不上传；全局互斥防重复创建与覆盖 |
| 中英文、深浅/系统主题、4 种发送键 | 保留；修复 Shift+Enter 和输入法误发送 |
| 线上 modern/classic/kimi 皮肤 | **有意删除**：一套组件结构，只有色彩主题与响应式布局 |
| PWA manifest、图片放大页面 | 重建 manifest/图标与原生模态预览，不复用旧独立页面 |
| 仓库中的自动模型生成话题名 | 线上已不调用；不恢复额外付费请求，首条文字本地命名 |

## 已确认的旧实现问题

这些是静态代码路径发现，不是声称对每种浏览器都做过复现：

1. 保存时删除附件图片 `dataUrl`，文本缩短到约 4,000 字符，刷新改变后续上下文。
2. 主记录和“备份”写入同一版数据，不是可靠的上一版本快照。
3. 设置草稿与全局模型选择耦合，新增/切换配置存在不一致路径。
4. 多套皮肤通过搬动真实 DOM 改布局，附件按钮/上下文按钮可能留在隐藏容器。
5. 输入框绝对定位配固定预留高度，附件/多行输入容易和消息阅读空间争抢。
6. 每个 token 重渲染全部消息并强制追底，阅读历史与长会话性能都受影响。
7. 无贯通前后端的用户停止；非流式 JSON 与截断流的错误路径不可靠。
8. Shift+Enter 未排除，中文输入法/快捷键行为欠明确。
9. 导入缺完整结构验证，已导入坏状态后才可能渲染报错。
10. 原始 Markdown HTML 直接进入 DOM；任意 URL 代理、图片代理与资源边界不足。
11. Gist“排除敏感信息”的注释与行为不符：模型 API Key 仍被上传；导出包含 Gist Token。
12. README“不会上传到任何服务器”与同源代理、手动 Gist 事实不符。

## 全新交互结构

- 桌面：固定会话导航 → 可控宽度阅读区 → 正常布局中的输入区。模型选择一直可见。
- 手机：单列聊天、可关闭抽屉、选择后自动收起，全屏设置；动态视口/安全区处理。
- 大设置页：模型与连接、通用、数据与备份、云端同步。保存范围明确。
- 停止、错误、部分回答、重试、上下文分段均为显式状态，不静默吞掉操作。
- 长历史分批展示，稳定历史消息 memo 化；上滑后不强迫滚回底部。

## 完成判定

不以“编译通过”或截图好看代替行为测试。必须覆盖：新用户配置、旧数据迁移、正文/思考流、停止与恢复、附件刷新、坏备份与配额失败、多标签页、Gist 无凭据备份、手机/桌面切换、Markdown 安全、后端准入/取消/SSRF 校验。

已知限制与真实测试范围以 README、迁移文档和测试代码为准。Git 历史保留用于审计，但新版工作树和运行时不包含旧实现。
